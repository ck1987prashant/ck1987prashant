# Documentation Directory

This directory contains documentation for plans, learnings, and project context to support business continuity and knowledge sharing.

## Purpose

When working with GitHub Copilot or any development activities, documenting plans and learnings helps:
- Create business continuity documents
- Provide context for future chat sessions
- Help other users understand previous decisions and approaches
- Maintain institutional knowledge

## Structure

- **plans/** - Documents containing planning information for features, issues, or initiatives
- **learnings/** - Documents capturing key learnings, insights, and best practices
- **templates/** - Templates for creating consistent documentation

## How to Use

1. When planning a new feature or issue, create a document in the `plans/` directory
2. Use the template from `templates/plan-template.md` as a starting point
3. Document your approach, decisions, and progress
4. After completion, capture key learnings in the `learnings/` directory
5. Reference these documents in PRs and issues for context

## Document Naming Convention

Use descriptive names with dates for easy reference:
- Plans: `YYYY-MM-DD-feature-name.md`
- Learnings: `YYYY-MM-DD-topic-name.md`

Example: `2025-12-03-structured-logging.md`
